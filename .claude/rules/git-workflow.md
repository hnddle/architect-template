# Git 워크플로우

이 문서는 브랜치·커밋·원격 작업 규칙을 정의합니다. 운영 모드는 두 가지이고, **프로젝트를 시작할 때 CLAUDE.md 「운영 모드」 줄에서 하나를 고릅니다.** 고르지 않았으면 모드 B로 봅니다(원격에 아무것도 나가지 않는 쪽이 안전합니다).

## 1. 모드 A — 팀 (브랜치 + PR)

- `main` 직접 push 금지. 모든 변경은 작업 브랜치 + PR로 합니다(deny가 main push · force push를 막는다).
- 작업 브랜치: `<type>/<짧은-설명>` (예: `feat/room-booking`, `fix/db-connection`) — type은 아래 커밋 type과 같은 어휘입니다. 스펙 킷 기능 브랜치는 `<NNN>-<short-name>` 이고 스펙 디렉터리 이름과 같습니다.
- 작업 브랜치 → main: PR 필수, squash merge 권장. force push 절대 금지.
- 템플릿 기본은 모드 B라 `.claude/settings.json` deny에 `Bash(git push*)` · `Bash(gh *)` 가 있습니다. 모드 A 프로젝트는 이 두 줄을 지웁니다.
- 스펙마다 작업 트리(워크트리)를 나누고 결정 단위로 커밋합니다.

## 2. 모드 B — 1인 로컬

개인 프로젝트를 로컬에서만 관리할 때입니다.

- 원격 · push · PR · 이슈 연동이 없습니다. `gh` 등 원격 도구를 쓰지 않습니다(기본 deny가 `git push` · `gh` 를 막습니다).
- 에이전트는 **커밋 · 브랜치 전환을 요청받을 때만** 합니다. 소유자가 작업을 묶어서 커밋합니다. 스펙마다 작업 트리를 나누지 않습니다.
- 여러 세션이 한 작업 트리를 같이 쓸 수 있습니다. 남의 미완성 변경이 섞여 있으므로 작업 트리를 되돌리는 명령(reset · checkout -- · clean · stash)을 쓰지 않습니다.
- 스펙 킷의 「스펙 만들 때 브랜치 생성」 훅은 끄고, 활성 스펙은 `.specify/feature.json` 으로 고릅니다. 이 파일은 공유 포인터라 바꾸면 보고합니다.
- 문서 양식이 티켓 링크 · `Blocked by` 를 요구하면 이슈 트래커 대신 로컬 문서 경로 · 스펙 번호를 적습니다.
- 나중에 push를 요청받으면 먼저 원격 주소와 커밋 작성자(`git config user.email`)가 이 프로젝트의 계정인지 확인합니다. 개인 · 회사 계정이 섞여 다른 조직 저장소에 올라가면 되돌리기 어렵습니다.

## 3. 커밋 메시지 (두 모드 공통)

```
<type>(<scope>): <한글 subject>
```

type: `feat`(기능 추가) · `fix`(버그 수정) · `docs`(문서) · `style`(포매팅, 코드 변경 없음) · `refactor`(기능 변경 없는 구조 개선) · `perf`(성능) · `test`(테스트만) · `chore`(빌드 · 설정 등) · `ci`(CI 설정).

예: `feat(reservation): 같은 회의실 겹침 예약 거절 추가`

- 결정 번호가 있으면 subject 끝 괄호에 둡니다: `fix(reservation): 취소한 예약도 이력에 남김 (D-001)`.
- 본문은 무엇이 문제였나 → 원인 → 고친 방법 → 검증(돌린 명령 · 시험 수 · 측정값) 순서입니다.
- 여러 세션의 변경이 한 커밋에 섞이면 그 사실과 「중간 상태가 함께 들어 있다」를 본문에 적습니다.
- 크게 갈아엎기 전에는 되돌릴 지점 커밋을 먼저 만듭니다.

## 4. 함께 지킬 것

- 테스트는 구현과 같은 커밋에 넣습니다(`testing.md`).
- 하네스 파일(`CLAUDE.md` · `.claude/**`)은 작업 중 임의로 고치지 않습니다. 고칠 점은 보고(또는 plan의 「문서 갱신 제안」)로 남기고, 소유자가 지시했을 때 고칩니다. 예외는 `CLAUDE.md` 의 `SPECKIT START/END` 블록과 결정 색인 새 행입니다(`decisions` §7).
- `.env` · 백업 · 로컬 시드 · 개인 IDE 설정 · 찌꺼기(`~$*` · `.DS_Store` · `*.bak-*`)는 커밋하지 않습니다(`.gitignore`).

요약 : 모드를 먼저 고르고, 원격은 요청과 계정 확인 뒤에만, 커밋은 원인과 검증을 담습니다.
