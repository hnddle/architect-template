# 보안 규칙

이 문서는 구현 시 지켜야 할 보안 규칙과 각 규칙의 **현재 강제 수단**을 정의합니다. 기준은 OWASP Top 10:2025이며, §6에 전체 매핑이 있습니다.

강제 수단은 세 가지뿐이며, 표에는 실제로 있는 것만 적습니다. 템플릿 상태에서는 코드가 없으므로 「시험」은 없습니다 — 스택을 고르고 시험을 만든 규칙만 「시험」으로 바꿔 적습니다.

| 수단 | 무엇 | 한계 |
| --- | --- | --- |
| deny | `.claude/settings.json` 의 `permissions.deny`. 도구 호출을 실행 전에 막는다 | 패턴 일치라 다른 표기로 우회된다. 안전띠다 |
| 시험 | 규칙을 코드로 확인한다 | 시험이 있는 규칙만 |
| 리뷰 | 사람 · 리뷰 에이전트가 확인한다 | 놓칠 수 있다. 반복되면 시험으로 승격 |

실행 전 차단 훅(hook)은 없습니다. 훅이나 deny 항목을 바꾸면 아래 표도 같이 고치고, 존재하지 않는 강제 수단을 적지 않습니다.

## 1. 시크릿·암호화

| 규칙 | 현재 강제 수단 |
| --- | --- |
| 소스코드에 비밀키·API 키·비밀번호·토큰 하드코딩 절대 금지 | 리뷰 |
| 모든 시크릿은 환경변수(또는 시크릿 저장소)로 로드 (`code-principles.md` §5-III). 견본 파일(`.env.example`)에는 값 없이 이름 · 설명만 | 리뷰 |
| 로컬 시크릿 파일(`.env`)은 절대 커밋 금지 | `.gitignore` + deny(`.env` 읽기 · 편집) |
| 키 파일(`id_rsa`, `*.pem`, `*.key`, `credentials.json`) 읽기/쓰기 금지 | deny(읽기) + 리뷰 |
| 민감 데이터는 전송 시 TLS, 저장 시 암호화. 검증된 표준 라이브러리만 — 자체 구현 금지 | 리뷰 |
| **운영 설정은 위험한 상태로 뜨지 않는다** — 필수 시크릿이 없거나 일부만 있으면 빠진 이름을 대며 기동 실패. 개발용 스위치(인증번호를 응답에 싣기 · 콘솔 발송기 · API 문서 노출 등)가 켜져 있으면 기동 거부 | 리뷰 |
| **QA 환경은 자기 서명 키를 쓴다.** 운영 데이터 사본이어도 토큰 서명 키 · 초기 계정 비밀은 버리는 값을 준다. 토큰 내용을 저장소 조회 없이 믿는 서비스에서는 운영 키로 QA에서 만든 토큰을 운영이 받아 주기 때문이다 | 리뷰 |

## 2. 입력·데이터 경계

| 규칙 | 현재 강제 수단 |
| --- | --- |
| 경계에서 모든 외부 입력을 스키마로 검증(요청 본문마다 검증 선언). 검증 실패와 무결성 위반(중복 · 버전 충돌)을 다른 오류로 구분 — HTTP API면 400 · 409 | 리뷰 |
| 질의는 파라미터 바인딩만 — 문자열 직접 조합 금지(SQL · 셸 · 템플릿 모두) | 리뷰 |
| 파일 업로드: 처리 전 파일 타입과 크기 검증 | 리뷰 |
| 사용자 제공 URL로 서버가 요청을 보낼 때는 허용 목록으로 검증 (SSRF 방지) | 리뷰 |
| 신뢰할 수 없는 데이터의 역직렬화 금지. 직렬화 포맷은 스키마 기반으로 한정 | 리뷰 |
| CSV · 스프레드시트 내보내기는 수식으로 시작하는 칸(`=` `+` `-` `@` 탭 · CR)을 무력화한다 | 리뷰 |
| LLM에 넣는 외부 텍스트(문서 · 웹 · 사용자 입력)는 지시가 아니라 데이터다. 그 출력으로 도구 호출 · 쓰기 동작을 할 때는 허용 목록과 사람 확인을 둔다 | 리뷰 |

## 3. 인증·접근 통제

| 규칙 | 현재 강제 수단 |
| --- | --- |
| 모든 진입점: 처리 전 반드시 인증 검증. "내부에서만 호출된다"는 가정 금지 | 리뷰 |
| 접근 통제는 기본 거부(Deny by Default). 객체 접근 시 소유권·권한을 서버에서 검증 (IDOR 방지). 남의 객체는 **없는 것과 같은 응답** — 존재를 드러내지 않고, 구별은 감사 기록에만 | 리뷰 |
| 비밀번호: 최소 8자(다중 인증이 없으면 더 길게), 검증된 느린 해시(argon2id · bcrypt 등 — 평문·단순 해시 금지). 조합 규칙(특수문자 강제)은 두지 않는다. 빈 값과 해시 함수의 입력 상한 초과는 거부 — 넘는 바이트가 조용히 잘리면 다른 비밀번호와 같아진다(bcrypt는 72바이트) | 리뷰 |
| 비밀번호 규칙은 **새로 정할 때만** 검사한다. 규칙 전에 정한 비밀번호의 로그인은 막지 않는다 — 보안 강화가 기존 사용자를 잠그면 안 된다 | 리뷰 |
| 인증 시도 횟수 제한(계정 단위), 로그인 시 세션 재발급. 시도 · 감사 기록은 본 처리의 트랜잭션과 분리해 실패해도 남긴다. 비밀번호 재설정 시 살아 있는 세션 · 갱신 토큰 전체 무효화 | 리뷰 |
| 남이 정한 초기 비밀번호 · 인증 코드는 응답 · 감사 · 로그 · 저장소 어디에도 평문으로 남기지 않는다 | 리뷰 |
| CORS: 허용 오리진 명시적 제한 (`*` 금지) | 리뷰 |
| 최상위 관리자 역할은 자기 권한을 낮춰 스스로 잠그지 못한다(권한 상승 방지 비교에서 최상위의 복구 경로를 남긴다) | 리뷰 |

## 4. 설정·의존성·로그

| 규칙 | 현재 강제 수단 |
| --- | --- |
| 기본 자격 증명 사용 금지, 불필요한 기능·진입점·샘플 비활성화, 프레임워크 보안 기본값 유지 | 리뷰 |
| 의존성은 버전 고정(잠금 파일 커밋). 알려진 취약점이 있는 버전 금지. 새 의존성은 출처 · 유지 상태를 보고 더한다 | 리뷰 |
| 로그 위생: 시크릿·토큰·민감 데이터 절대 로깅 금지 | 리뷰 |
| 보안 이벤트(로그인 실패, 접근 거부, 검증 실패)는 감사 가능하게 로깅 — 단, 로그에 민감 데이터 본문 금지 | 리뷰 |
| 사용자에게 보이는 오류 메시지에 내부 구조(스택·쿼리·경로) 노출 금지. 예상하지 못한 오류는 열린 채(fail open) 넘어가지 않고 거부로 끝낸다 | 리뷰 |
| **결제 정보는 카드번호 끝 4자리만** 저장한다. 메모 · 비고 칸에 12자리 이상 이어진 숫자가 들어오면 거부한다(카드번호 전체가 새어 들어오는 길을 막는다) | 리뷰 |

민감 데이터(개인정보·인증정보·결제정보)의 구체 필드 목록과 마스킹·보존 정책은 프로젝트 NFR에 한 곳으로 정의하고 전 문서에서 일치시킵니다. 로그 · 오류 · 시험 픽스처에 넣지 않습니다(픽스처 값은 `conventions.md` §4의 가짜 값).

## 5. 실행 환경·파일 안전

| 규칙 | 현재 강제 수단 |
| --- | --- |
| 파괴적 명령 금지 — `rm -rf`, force push, main 직접 push, `sudo`, `chmod 777`, 원격 스크립트 파이프 실행(`curl \| sh`), 검증 우회(`--no-verify`). 스택을 고르면 그 스택의 파괴적 명령(데이터 볼륨 삭제 · 인프라 적용/파기)을 deny에 더한다 | deny + 리뷰 |
| 운영 데이터에 삭제 · 구조 변경을 직접 실행하지 않는다. 스키마 변경은 멱등 이행으로만 하고, 검증된 백업을 먼저 뜬다 | 리뷰 |
| 작업 트리를 되돌리는 git 명령(reset · checkout -- · clean · stash · branch -D)은 사용자 승인 후에만 | 권한 확인(allow 에 넣지 않는다) + 리뷰 |
| 외부 네트워크 통신(curl · wget · ssh · scp)은 localhost만. 의존성 설치 · 다운로드는 사용자 승인 후 | 권한 확인 + 리뷰 |
| 원격 작업(push · PR · 이슈)은 소유자 명시 요청 시에만 — 운영 모드는 `git-workflow.md` | deny(모드 B는 push · `gh` 전체, force · main은 늘) + 리뷰 |
| 프로젝트 밖 파일 쓰기 금지 — 세션 임시 디렉터리는 예외 | 리뷰 |
| 파일 삭제는 복구 가능한 방식 우선(휴지통으로 보내는 명령). `rm`을 폴백으로 쓰지 않음 | 리뷰 (`rm -rf`는 deny) |
| `mv`·`cp`는 `-n`(덮어쓰기 금지) 후 결과 확인 — 대상이 있으면 조용히 건너뛴다 | 리뷰 |
| 외부 저장소의 훅·에이전트 설정·스크립트는 검토 없이 적용 금지 | 리뷰 |
