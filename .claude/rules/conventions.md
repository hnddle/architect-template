# 코딩·네이밍 규칙

스택과 무관한 표기 규칙입니다. 언어별 문법 · 포매팅은 그 언어의 공식 스타일 가이드를, 설계 원칙은 `code-principles.md`를 따릅니다.

## 1. 코드 네이밍

- 식별자 표기는 **선택한 언어의 표준 컨벤션**을 따릅니다. 한 코드베이스에서 표기법을 혼용하지 않습니다.
- 이름은 발명하지 않습니다 — 스펙·아키텍처 문서에 정의된 컴포넌트·도메인 용어를 그대로 씁니다(용어 정본은 `docs/01.requirements/glossary.md`).
- 이름이 길어지는 것보다 모호한 것이 나쁩니다. 축약어는 도메인 표준(API, DB 등)만 허용합니다.
- boolean은 `is/has/can` 접두, 함수는 동사로 시작합니다.

## 2. 데이터 네이밍과 데이터 규칙

관계형 DB를 쓸 때의 기본값입니다. 다른 저장소(문서 DB · 키-값)를 고르면 같은 원칙(한 표기 · 이름에 뜻 · 제약에 이름)을 그 저장소의 관례로 옮겨 이 표를 고칩니다.

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 테이블 | snake_case, **복수형** | `reservations`, `audit_logs` |
| 컬럼 | snake_case, PK는 `id`, FK는 `<table단수>_id` | `room_id` |
| 인덱스 | `idx_<table>_<col>` | `idx_reservations_room_id_starts_at` |
| 유일 제약 · 유일 인덱스 | `uq_<table>_<cols>` | `uq_reservations_idempotency_key` |
| 검사 제약 | `ck_<table>_<규칙>` | `ck_reservations_period` |

- **스키마 정본은 한 곳입니다.** 정본 위치와 이행(migration) 방식은 스택을 고를 때 정해 `CLAUDE.md`에 적습니다. 어떤 방식이든 이행은 **멱등**이고(두 번 돌려도 같은 결과) 적용 순서가 파일로 남아야 합니다.
- **지우기는 소프트 삭제가 기본입니다.** 행은 남기고 `active = false` 또는 `deleted_at`을 채웁니다. 같은 자연 키(이름 · 번호)로 다시 만들면 새 행이 아니라 지운 행을 되살리고, 지운 행이 같은 값의 재등록을 막지 않습니다(`product-judgement` §2). 개인정보는 예외입니다 — 지우거나 익명화하고 되살리지 않습니다.

## 3. 코드 상수 · 식별 문자열

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 오류 코드 | `UPPER_SNAKE`. 사람이 읽는 문구와 따로 둔다 | `VALIDATION_FAILED` · `VERSION_CONFLICT` · `DUPLICATE_DETECTED` |
| 기능 모듈 · 화면 코드 · 권한 이름 | `UPPER_SNAKE`. 저장은 코드로 하고 화면 이름은 따로 둔다 — 라벨을 바꿔도 이행이 필요 없다 | `RESERVATION` |
| 환경변수 | `UPPER_SNAKE` | `SESSION_SIGNING_KEY` |
| 화면에 보이는 글 | 코드 이름을 그대로 보이지 않는다 | `ACTIVE` → 「사용 중」 |

## 4. 예시 값은 가짜만

화면의 placeholder · 「예:」 힌트 · 오류 문구의 예 · 시험 픽스처 · 시연 시드 · 문서의 예시에는 아래 가짜 값만 씁니다. 실제 사람 · 고객 · 회사에서 온 이름 · 번호 · 연락처 · 주소 · 수량은 쓰지 않습니다 — 공식 화면이나 문서에 실제 값이 예시로 박히면 개인정보 · 영업 정보 문제가 되고, 지우려면 전체를 다시 뒤져야 합니다.

- 회사 「예시회사」 · 사람 「홍길동」 · 전화 「010-1234-5678」 · 이메일 「user@example.com」 · 도메인 `example.com` · 주소 「○○시 ○○로 123」
- 예시 도메인 대상 「회의실 A」 · 금액 「1,234원」 · 번호 「1234」
- 예외: 공공 기준 자료(행정구역 · 역 · 공공 데이터셋 기록)는 실제 값에 출처 · 기준일을 붙여 씁니다. 사람에 붙는 값은 가짜입니다.

프로젝트를 시작하면 업무 도메인의 가짜 값(식별자 형식 등)을 이 목록에 더합니다. 템플릿의 예시 도메인(공유 회의실 예약)은 `scripts/check-leaks.sh --strict` 가 남은 자리를 알려 줍니다.

## 5. `ponytail:` 주석 — 의도적 단순화의 상한

일부러 단순하게 만든 곳(전역 잠금 · 쪽 나누기 없음 · 프로세스 메모리 카운터 · 전체 읽기 후 계산)에는 `ponytail:` 주석으로 **어디까지 버티는지(상한)와 넘으면 무엇으로 바꾸는지(확장 경로)**를 적습니다. 다음 사람이 「왜 이렇게 허술한가」를 다시 조사하지 않게 하고, `ponytail:` 을 모으면 기술 부채 목록이 됩니다.

```
// ponytail: 회의실 목록을 쪽 나누기 없이 읽는다 — 회의실이 200개를 넘으면 쪽 나누기를 더한다
```

- 상한과 확장 경로를 한 줄에 적습니다. 조건 없는 「나중에 개선」은 쓰지 않습니다.
- 무상태 · 멱등 같은 원칙의 예외를 둘 때도 같은 주석으로 이유를 남깁니다.
- 접두는 검색 키입니다. 다른 낱말로 바꾸려면 이 절과 `CLAUDE.md`를 같이 고치고 한 가지로만 씁니다.

## 6. 금지

- 디버그 출력 커밋 금지
- TODO/FIXME는 추적 번호(스펙 번호 · 결정 번호 · 티켓) 없이 남기지 않습니다. 의도적 단순화는 TODO가 아니라 `ponytail:` 주석입니다
- 주석 처리된 죽은 코드 커밋 금지 — git이 기억합니다

포매터 · 린터 · 정적 검사는 스택을 고를 때 정하고 실행 명령을 `CLAUDE.md` 「명령」 표에 적습니다.

요약 : 이름은 문서에서 가져오고, 지우기는 남기며, 예시는 가짜로, 단순화는 상한과 함께 적습니다.
