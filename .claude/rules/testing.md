# 테스트 규칙

스택과 무관한 테스트 원칙입니다. 시험 러너 · 실행 명령은 스택을 고를 때 정해 `CLAUDE.md` 「명령」 표에 적습니다.

## 1. 구조

- **테스트 파일은 소스 구조를 미러링합니다**: 소스 모듈과 테스트 모듈이 1:1로 대응해야 합니다.
- **테스트 이름은 시나리오를 서술합니다**: `{대상}_{시나리오}_{기대결과}` — 이름만 읽고 무엇이 깨졌는지 알 수 있어야 합니다. 한국어 이름도 됩니다.
- **테스트 본문은 Given-When-Then 구조로 작성합니다**: 준비(Given) → 실행(When) → 검증(Then)을 구분하고, 한 테스트에 When은 하나만 둡니다.
- **최소 요건**: 모든 공개 함수 · 진입점에 최소 1개 테스트. 스펙의 수용 기준(AC) 하나가 시험 하나 이상이 됩니다. 시험 머리 주석에 요구 · 결정 ID를 적어 추적합니다.
- **공유 setup은 픽스처/헬퍼로**: 테스트 간 복붙 금지, 상태 공유 금지 — 각 테스트는 독립 실행 가능해야 합니다.
- **픽스처에 실제 고객 데이터·민감정보 금지**: 가짜 값(`conventions.md` §4)과 생성기를 씁니다 (`security.md` §4).

## 2. 실제 저장소 · 통합 시험

- **저장 계층은 실제 테스트 인스턴스로**: DB·외부 저장소는 운영과 같은 종류의 실제 인스턴스(일회용 컨테이너 · 임시 DB)를 띄우고, 외부 API만 가짜(정해진 답을 주는 것 · 보낸 것을 기록하는 것)를 씁니다. 첫 기능부터 그렇게 씁니다 — 목(mock)만으로 통과한 첫 구현은 멱등 키 · 제약 · 권한 경계를 하나도 확인하지 못한 채 끝납니다.
- 단위 시험과 통합 시험(실제 저장소를 띄우는 것)은 이름이나 디렉터리로 구분해 따로 돌릴 수 있게 합니다. 구분 규칙은 `CLAUDE.md`에 적습니다.
- 경계를 우회한 쓰기는 저장소의 제약이 막는지 「실패 먼저」 시험합니다.
- 한 작업 트리에서 같은 시험 묶음 두 벌을 동시에 돌리지 않습니다 — 결과 파일 · 포트 · 임시 DB가 겹쳐 엉뚱한 실패가 납니다.

## 3. 시간

- **시계는 주입합니다.** 코드는 현재 시각을 직접 읽지 않고 시계를 받습니다. 단위 시험은 고정 시계, 통합 시험은 앞으로만 가는 시험용 시계를 쓰고 기대값을 그 시계의 「오늘」에서 셉니다.
- 날짜 · 시각을 다루는 시험은 기본 시간대 두 개(UTC와 서비스 시간대)에서 같은 결과여야 합니다. 실행 환경의 기본 시간대가 달라도 같은 기록이 같은 날짜에 묶이는지 확인합니다.
- **자정 직후 「오늘」 경계 함정**: 「지금 − N분」으로 저장하고 「오늘」로 조회하는 시험은 00:00 직후 N분 동안 기록이 전날로 떨어져 실패합니다. 이런 시험은 고정 시계로 고칩니다. 이미 있는 경계 시험이 자정 직후에만 깨지면, 변경 탓으로 보고 추적하기 전에 그 시간대가 지나 다시 돌립니다.
- 「오늘」을 시드하는 시연 · 캡처 스크립트는 날짜 인자를 받습니다(자정 직후에는 오늘이 비어 있다).

## 4. 실패 케이스 우선

- **실패 케이스 우선**: 스펙에 정의된 실패 시나리오(타임아웃, 인증 실패, 부분 실패, 중복/재시도)는 반드시 테스트로 존재해야 합니다 — happy path만 있는 테스트는 미완성입니다. 시험 묶음은 실패 시나리오를 앞에 둡니다.
- 재시도 흐름은 같은 입력을 두 번 보내 결과가 같은지 시험합니다(`code-principles.md` §5 멱등성).
- **데이터 이행**은 데이터가 든 저장소(운영 사본 또는 시드)에 **두 번** 돌려 같은 결과인지, 업무 총량(건수 · 합계)이 그대로인지, 스키마 정본과 구조 차이가 없는지 확인합니다. 바꾸는 기존 값은 명시한 것뿐이어야 합니다.

## 5. 단위 시험으로 못 잡는 것

모의 환경(가짜 DOM · 에뮬레이터 · 목 서버)은 실제 환경의 생명주기 · 포커스 · 배치 · 타이밍 결함을 재현하지 못합니다. 저장 뒤 화면이 다시 그려지며 사라지는 알림, 「한 화면에 들어온다」 같은 배치 요구(화면 크기 목록으로 숫자 단언), 터치 · 키보드 분기, 실제 네트워크 지연에 기대는 흐름은 실제 환경(실브라우저 · 실기기 · 격리 스택)의 E2E로 확인합니다. 기능 묶음이 끝나면 역할 × 화면 크기로 전 화면을 한 번 돕니다.

## 6. 기준선과 승격

- **시험 기준선은 줄지 않습니다.** 작업 전 시험 수를 적어 두고, 작업 뒤 줄었으면 통과가 아닙니다. 기존 시험을 지우거나 단언을 약하게 고치지 않습니다. 바꿔야 하면 이유를 보고합니다.
- **규칙은 시험으로 승격합니다.** 「문서 + 리뷰」만인 규칙이 한 번 깨지면 시험 후보입니다(화면 글 규칙 · 의존 경계 · 보안 헤더 등).
- 모두 통과했는데 종료 코드가 0이 아니면 러너의 「처리되지 않은 오류」 출력을 먼저 봅니다.
- **테스트는 구현과 같은 커밋에 포함합니다** — 테스트를 뒤로 미루지 않습니다.

요약 : 커버리지 숫자보다 시나리오 커버리지입니다. 숫자를 채우기 위한 무의미한 테스트는 금지하고, 실제 저장소 · 고정 시계 · 실패 먼저로 씁니다.
