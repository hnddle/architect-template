## `UC-001` · 회의실 등록 · 수정

| 항목 | 내용 |
| --- | --- |
| **주 액터** | 관리자 |
| **사전조건** | 공통 사전조건(04 §4)을 통과했다 |
| **사후조건** | 회의실이 목록에 보이고 예약할 수 있다. 이름을 고치면 지난 예약에도 새 이름이 보인다(정정) |
| **대응 `CMP`** | `CMP-102` `CMP-101` |
| **근거 `FR`** | <FR-###> |
| **인터페이스** | 회의실 저장 · 수정 · 지우기 (계약은 `specs/<NNN>-<기능>/contracts`) |

**주 흐름 (목표)**

1. 관리자가 회의실 이름 · 정원을 입력하고 저장한다.
2. 시스템이 이름 1~50자 · 정원 1 이상을 검사한다.
3. 시스템이 같은 이름의 회의실이 없는지 보고 저장한다.
4. 시스템이 저장한 회의실을 목록에 보인다.

**실패 케이스**

| 조건 | 시나리오 (관리자 관점) | 대응 `FR`·`NFR` |
| --- | --- | --- |
| 같은 이름의 회의실이 이미 있음 | 거부되고 이미 있다는 안내가 보인다(`DUPLICATE_DETECTED`) | <FR-###> |
| **지운 회의실과 같은 이름** | 거부하지 않는다. 새 행을 만들지 않고 지운 회의실을 되살린다 — 지난 예약이 한 회의실로 이어진다 | <FR-###> |
| 예약이 남은 회의실을 지움 | 회의실은 목록에서 사라지지만 행은 남는다. 지난 예약은 회의실 이름을 그대로 보인다 | <FR-###> |
| 사내 사용자가 회의실을 고치려 함 | 요청 경계에서 거부된다 | <FR-###> |
