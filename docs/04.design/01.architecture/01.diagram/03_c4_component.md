> **문서 코드**: `CMP` — `CMP-1xx`(API)

> **상태**: 목표 상태 (골격)
> **작성일**: <YYYY-MM-DD>

이 문서는 컴포넌트 문서의 **목차이자 정본 표 세 개**(컴포넌트를 가진 컨테이너 · 코드 모듈 매핑 · FR/NFR 대응)를 담는다. 컴포넌트 사이의 관계 그림은 컨테이너별 문서(`03a` …)가 담당한다.

---

## 1. 컴포넌트를 가진 컨테이너

| 백 단위 | 컨테이너 | 문서 | 컴포넌트 수 |
| --- | --- | --- | --- |
| `CMP-1xx` | `CON-002` API 애플리케이션 | [03a_component_api.md](03a_component_api.md) | 검사 스크립트가 센다 |

- `CON-001` 웹 클라이언트는 화면 도메인이 늘면 `CMP-3xx` + `03c` 문서로 나눈다. 지금은 화면이 한 묶음이라 나누지 않았다.
- `CON-003` 알림 워커는 작업 하나짜리라 컴포넌트로 쪼개지 않았다. 작업이 늘면 `CMP-2xx` + `03b` 문서를 만든다.
- `CON-004`는 저장소라 컴포넌트가 없다.

## 2. 코드 모듈 매핑 (정본)

**컴포넌트 하나 = 그 컨테이너의 최상위 모듈 하나**다. 모듈 이름은 이 표에서 가져오고 코드가 이름을 발명하지 않는다. 계층은 모듈 안에만 둔다.

| CMP | 모듈 | 주 책임 | 담당 FR |
| --- | --- | --- | --- |
| `CMP-101` | `access` | 요청 경계 — 인증 확인 · 권한 판정. 판정은 여기 한 곳에만 있다 | <FR-###> |
| `CMP-102` | `room` | 회의실 목록 · 예약 규칙(예약 단위 · 최대 길이) | <FR-###> |
| `CMP-103` | `reservation` | 예약 만들기 · 바꾸기 · 취소 · 겹침 판정 · 변경 이력 | `FR-001`~`FR-005` (예시) |
| `CMP-104` | `notification` | 알림 발송 포트와 메일 어댑터. 벤더 SDK는 여기 밖으로 나오지 않는다 | <FR-###> |

**컴포넌트가 아닌 모듈**

| 모듈 | 무엇인가 |
| --- | --- |
| `shared` | 시계 · 공통 오류 형식처럼 여러 컴포넌트가 같이 쓰는 코드. 업무 규칙을 두지 않는다 |

## 6. 자체 점검

| # | 점검 항목 | 결과 |
| ---: | --- | :--: |
| 1 | 컴포넌트 이름이 계층 이름(`domain` · `service`)이 아닌가 | ✅ |
| 2 | 매핑표의 모듈이 컴포넌트와 1:1인가 | ✅ §2 |
| 3 | 활성 FR · NFR 전건이 대응표에 있는가 | ⚠️ 골격 — SRS 승인 뒤 채운다 |
| 4 | 분할 문서와 `CMP` 집합이 같은가 | ✅ `scripts/check-diagrams.sh` 통과 |

요약 : 컴포넌트는 **API 컨테이너 안의 네 모듈**(요청 경계 · 회의실 · 예약 · 알림)이고, 이 표의 이름이 곧 코드의 최상위 모듈 이름이다.
