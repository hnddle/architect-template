# 현행 업무 조사 — <업무 이름>

> **문서 성격**: 요구공학(`.claude/rules/requirements-engineering/requirements-pipeline`) **이전 단계**의 조사 자료. 사용자 · 현행 워크플로우 · 페인포인트 · 관찰된 문제를 **수집 · 기록**한다. 해결 방법 · 기능 · 시스템 구조는 **의도적으로 다루지 않는다.**
> **원자료**: <원문 · 화면 관찰 정리 링크> · <업무 데이터 파일 분석 링크> · <인터뷰 메모>
> **전제**
> - 참고 시스템은 **재구축 대상이 아니라 관찰 자료**다. 화면 · 용어 · 디자인은 참고만 하고 그대로 쓰지 않는다.
> - 원문 작성자와 참고 시스템 운영자는 서로 다른 워크플로우를 가질 수 있다. 둘의 차이는 결함이 아니라 **고객사별 편차의 표본**이다.
> - 현재 자료는 **원문 <n>건 + 참고 시스템 <n>건 + 업무 파일 <n>건 + 인터뷰 <n>건**이다. 표본이 적으면 §7의 조사 질문으로 확장한다.
>
> **표기**: 【사실】 원문 · 화면 · 파일에서 확인된 것 / 【추정】 사실에서 유도한 판단(근거 병기) / 【질문】 조사로 확인할 것
